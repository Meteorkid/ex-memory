# 危机干预文案审阅流程

> 这份清单的作用对象是**可能正在考虑自杀的人**。请把它当作发布前的强制关卡，
> 而不是走过场的核对表。

## 当前状态

`content/crisis_resources.zh-CN.json` 的 `reviewed = false`。

在此期间系统的行为是：

- 危机识别照常工作，命中后照常中断人格模拟
- 但只展示 `fallback_message`，**不展示任何热线号码**
- 服务启动时打印警告

这是刻意的降级：**宁可不给号码，也不给错号码。** 一个打不通的电话，
在那个时刻可能比没有电话更伤人。

## 为什么号码不能由 AI 填

仓库里 `12356` 那一条标着 `verified_at: ""`，`source` 写的是百度百科词条。
这是一个**调研候选**，不是核实结果：

- 百科是可编辑来源，不能作为可直接上线的依据
- 调研时未能取得卫健委原始文件（官网返回 412，搜索引擎转向验证码）
- 号码的覆盖时段、是否收费、是否需要转接，这些都无法从二手来源确认

所以它只是帮你省掉「从零开始查」的一步，**核实仍然必须由人完成**。

## 审阅人需要具备的资质

至少满足其一：

- 注册心理师 / 精神科执业医师
- 有危机干预热线一线工作经验
- 所在机构的心理健康专业负责人

**不接受**：产品经理、工程师、法务单独签字。他们可以参与，但不能作为审阅人署名。

## 审阅清单

### 第一部分：文案

逐条确认 `fallback_message` 与 `reviewed_message`：

- [ ] 明确说明「无法继续这段对话」，不含糊
- [ ] 表达关切，但**不做诊断**（不出现「你可能有抑郁症」这类判断）
- [ ] **不含准治疗性内容**：「深呼吸」「你的感受是正常的」「会好起来的」这类
      话需要执业资质才能说，且在错误的时机会适得其反
- [ ] 不承诺平台做不到的事（「我会一直陪着你」）
- [ ] 不使用可能被理解为责备的表述（「不要想不开」「为了家人考虑」）
- [ ] 指向的是**现实中的人与机构**，不是产品自身的其他功能
- [ ] 语气与本产品的整体调性一致，但明确是**平台在说话**，不是「ta」在说话
- [ ] 长度适中——那个状态下的人读不进长段落

### 第二部分：热线

对 `hotlines` 数组里每一条：

- [ ] **实际拨打过**，确认接通
- [ ] 记录覆盖时段（24 小时？工作日？）填入 `hours`
- [ ] 确认是否收费、是否需要转接，填入 `free` 与 `note`
- [ ] 确认服务范围是否覆盖产品的目标用户地区
- [ ] 在该条上填写 `verified_at`（核实日期）

未填 `verified_at` 的条目**不会展示给用户**，但会在日志里告警。
如果所有条目都没通过核实，系统会退回不承诺热线的兜底文案。

### 第三部分：签字

三个字段全部填写后，`reviewed` 才会真正生效：

```json
"reviewed": true,
"reviewed_by": "姓名（资质编号或机构）",
"reviewed_at": "YYYY-MM-DD",
"hotlines_verified_at": "YYYY-MM-DD"
```

**这不是靠自觉。** `core/safety/resources.py` 会校验这三个字段齐备，
缺任何一个都按未审阅处理并记录错误日志。测试
`test_reviewed_true_without_signoff_is_treated_as_unreviewed` 钉死了这个行为。

## 复审周期

建议每 6 个月重新核实一次热线有效性，或在以下情况发生时立即复审：

- 收到用户反馈号码打不通
- 监管发布新的心理援助服务规范
- 产品扩展到新的服务地区

复审后更新 `hotlines_verified_at`。
