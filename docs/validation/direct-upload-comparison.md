# Ex-Memory 与直接上传聊天资料的配对验证

状态：待真实用户执行。本机合成数据验证只证明导入、权限、生成和首聊流程；不证明人物还原、模型质量或付费需求。

## 验证问题

在相同底座模型和相同合法来源材料下，Ex-Memory 是否减少整理与持续使用的工作，同时保持事实正确、会话稳定？

## 对照设置

- A：Ex-Memory，记录代码版本、导入配置、模型供应商与精确模型名、采样参数。
- B：同一模型直接使用同一份聊天文件，提供认真准备的角色说明、回答依据和纠正方式；允许使用对照产品已有的项目、文件与持久记忆功能。不可用一个故意简陋的提示词作对照。
- 两组使用相同有效资料、提问及模型版本；若模型/文件大小或产品能力无法对齐，记录差异并把该对比列为“产品总体体验”，不把差异归因于 Ex-Memory 的记忆机制。
- 若完整文件超出上下文，记录限制，使用该产品推荐的文件检索方式；不截掉对照的关键材料。输入/输出 token 和费用分别记录。
- 参与者以本人资料或获得明确授权的资料建镜像；样本去除无关敏感字段，设置删除日期。不给项目方收集原始聊天作默认前提。

## 每位用户的任务

| 阶段 | 相同任务 | 观察项 |
|---|---|---|
| 首次体验 | 从持有导出文件到得到第一条有依据的回复 | 主动操作分钟、等待分钟、点击/重传次数、求助次数、失败原因 |
| 事实查询 | 问 3 个材料明确支持的问题 | 正确/错误/材料不含；依据能否定位；是否凭空补全 |
| 缺失信息 | 问 1 个材料没有答案的问题 | 是否明确不确定，是否捏造具体事实 |
| 多次使用 | 隔天开启新会话问同一事实及相关问题 | 是否需重复上传/重讲、答案与资料是否一致 |
| 更正 | 修正一个误识别的昵称或明确事实，再新开会话 | 更正耗时、是否持续生效、旧信息是否仍被错误使用 |
| 新增材料 | 导入一份含新事实或较新日期变化的材料 | 更新耗时、是否影响旧资料、是否区分历史与当前信息 |
| 恢复 | 一次失败/刷新后继续原任务 | 是否找回进度、是否重复建镜像/重复存资料、人工补救耗时 |

用户为两组交替顺序或随机顺序，避免先做一组就熟悉任务造成固定偏差。事实评价与“像本人”的主观评价分开；盲评时隐藏产品标签，提供材料依据并允许“不知道”。

## 如何判断

1. 先检查质量：有没有更高的事实错误率、忽略纠正、串人物或无法恢复的导入失败。时间节省不能掩盖这些问题。
2. 再看每位用户的配对差值：主动操作时间、成功任务数、维护与求助次数；报告中位数与逐人结果，小样本不宣布市场成立。
3. 事先写下继续投入门槛，例如“多数用户在第二周的实际任务中主动复用，且维护耗时明显下降”。具体数值由可承受的支持成本和用户痛点确定，不在看完结果后调整。
4. 付款是独立结果；技术准确率、口头喜欢、访问次数都不能替代实际付款。
5. 底座模型升级后，用冻结的一组材料和问题重跑 A/B；若直接上传方案已经达到同等质量与成本，更新定位或停止扩张，不延用旧模型的优势结论。
