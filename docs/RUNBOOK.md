# 运营手册

> 覆盖 PRD 第 12.2 节要求的流程（NFR-076 / NFR-077 / NFR-078）。
> 这份文档的作用是让「出事之后该找谁、按什么顺序做」在事发前就写清楚。

## 定时任务

服务本身不做调度，以下任务需配 cron。周期是建议值。

| 任务 | 命令 | 建议周期 | 说明 |
|---|---|---|---|
| 过期对话清理 | `python run.py` → `/cleanup` | 每天 04:00 | 留存策略靠它执行，不跑等于没有留存期 |
| 主动消息判定 | `/proactive-tick` | 每小时 | 判定逻辑自带免打扰与每日上限，跑勤不会打扰 |
| 平台快照 | `/snapshot --label daily-$(date +%Y%m%d) --verify` | 每天 03:00 | `--verify` 会真取回来比对 |
| 订阅过期处理 | `python -c "from core.payments import expire_overdue; expire_overdue()"` | 每天 01:00 | 过期订阅降回免费套餐 |
| 僵尸任务回收 | 服务启动时自动执行 | — | 也可手工调 `core.tasks.reclaim_stale()` |

## 告警与值班

### 必须有人响应的信号

| 信号 | 含义 | 首要动作 |
|---|---|---|
| `exmemory_safety_events_total{type="crisis"}` 上升 | 危机事件增多 | **24 小时内人工复核**高置信度事件 |
| `exmemory_kv_degraded == 1` | 共享状态降级为进程内 | 限流已退化为每副本各自计算，尽快恢复 Redis |
| `exmemory_llm_calls_total{outcome="failure"}` 占比升高 | 供应商异常 | 查熔断状态，必要时切备用供应商 |
| 5xx 率 > 0.5% | 服务异常 | 按事故流程处理 |
| `exmemory_task_queue_depth` 持续增长 | worker 处理不过来 | 扩 worker 线程或副本 |

指标端点 `/metrics` 需要 `METRICS_TOKEN`，**未配置时直接 404**——指标暴露
的是运营信息，默认公开不可接受。

### 人力投入（NFR-077）

以下两项是**持续人力成本**，不是一次性开发，做排期与定价时必须计入：

- **危机事件人工复核**：高置信度事件 24 小时内。复核队列在
  `GET /api/admin/safety/reviews`，需要管理员权限。
- **被模拟者投诉与近亲属主张处理**：`GET /api/admin/subject-requests`，
  响应时限 15 个工作日。

管理员权限只能通过 CLI 授予：`python run.py` → `/grant-admin {用户名}`。
刻意不做「第一个注册的用户自动成为管理员」这类便利逻辑。

## 事故分级与响应

| 级别 | 判据 | 响应时限 | 通报 |
|---|---|---|---|
| P0 | 用户自伤事件、跨用户数据泄漏、大规模数据丢失 | 立即 | 立即上报负责人 |
| P1 | 服务不可用、支付异常、合规功能失效（危机干预/内容审核不工作） | 30 分钟 | 当日 |
| P2 | 单功能异常、性能劣化 | 4 小时 | 周报 |
| P3 | 体验问题、非关键缺陷 | 下个迭代 | — |

**P0 中的自伤事件有特殊流程**：先确认危机干预链路是否正常工作（`pytest
tests/test_crisis_route.py`），再复盘该用户的 `safety_events`。任何情况下
不得联系用户本人做「回访」——平台不具备这个资质。

### 复盘

P0/P1 必须复盘，产出：时间线、根因、影响面、修复措施、防复发措施。
防复发措施要落成**会失败的测试**，不是文档里的一句话——这个仓库里每个
重大缺陷的修复都配了一条在修复前会红的用例。

## 变更管理

- 所有改动走 PR，CI 必须全绿。CI 里有四道单独门禁：删除完整性、安全闸门
  顺序、拟真度指标、覆盖率分层。
- **数据平面改动**（迁移、存储后端切换）额外要求：先在副本上演练，且确认
  `pytest tests/test_account_rights.py::TestDeletionCompleteness` 仍通过——
  删除能力因架构升级而倒退是最容易发生也最难发现的合规事故。
- 回滚：镜像按 tag 发布，回滚即回退 tag。数据库迁移目前只前滚不回滚，
  破坏性迁移前必须先快照。

## 安全响应（NFR-078）

- 漏洞接收：在 README 与官网留一个安全联系邮箱，承诺 3 个工作日内首次响应。
- 修复时限：高危 7 天，中危 30 天，低危随迭代。
- 依赖漏洞由 CI 的 `pip-audit` 阻断；高危不允许合并。
- **不要在公开渠道讨论未修复的漏洞细节。**

   `terms` 为空，靠第三方主通道兜底；主通道未接入时这三类无本地防护。
