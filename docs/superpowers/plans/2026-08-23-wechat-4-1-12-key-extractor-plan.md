# 微信 4.1.12 当前账号全库密钥提取器实施计划

> 日期：2026-08-23
> 依据：`docs/superpowers/specs/2026-08-23-wechat-4-1-12-key-extractor-design.md`

## 阶段 1：建立定位反馈环

1. 固化已验证的 `CCKeyDerivationPBKDF` 动态锚点和 `(32, 16, 256000)` 参数模型。
2. 从微信运行状态解析唯一当前账号目录，拒绝猜测或批量处理其他账号。
3. 用 LLDB 宿主侧回调捕获一次账号密码并可靠分离。
4. 在同一助手进程中派生、验证并保留当前账号全库 key，随后清零。

## 阶段 2：测试先行实现核心组件

1. 为数据库清单、匿名账号标识、全覆盖门禁编写失败测试。
2. 为候选参数解析、首页密码学校验和敏感信息清理编写失败测试。
3. 为定位候选评分与伪 LLDB 事件流编写失败测试。
4. 实现最小组件使相关测试通过。

## 阶段 3：实现混合提取器

1. 实现 LLDB 断点提取唯一路径，确保短暂停顿和可靠分离。
2. 删除诊断脚本与旧 C 内存扫描路径。
3. 统一候选验证、进程内 key 映射和当前账号全覆盖门禁。
4. 接入现有专家工作流和 UI 状态接口。
5. 增加密钥规则确认门禁，并在提取前、账号不匹配和完成后三处展示不同账号需分别提取的说明。

## 阶段 4：验证与收尾

1. 运行相关 pytest、完整 pytest 和 Ruff。
2. 在微信 4.1.12 上完成当前账号触发和 28/28 全库捕获验证。
3. 对全部数据库执行首页校验与 SQLCipher 元数据只读查询。
4. 验证首次导入、切换账号、任务重启和密钥失效四种场景的重新提取提示。
5. 检查无 key/salt 泄漏、无遗留 LLDB/helper 进程。
6. 更新用户文档和 Obsidian 技术笔记，提醒账号密钥隔离及恢复 SIP。

## 停止条件

- 三个独立定位假设均失败时停止修改，重新评估断点架构。
- 无法在不输出密钥的情况下验证候选时停止真机探针。
- 任一数据库未覆盖时不得宣称实现完成或进入解密。
