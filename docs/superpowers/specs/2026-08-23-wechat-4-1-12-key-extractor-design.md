# 微信 4.1.12 当前账号全库密钥提取器设计

> 日期：2026-08-23
> 状态：待用户最终审核

## 目标

在 Apple Silicon macOS 和微信 4.1.12 环境中，为 `ex-memory` 实现当前登录账号的事务式数据库密钥提取与导入流程。一次任务必须覆盖当前账号目录中的全部数据库；只有每个加密数据库都取得并验证了对应密钥，任务才可进入快照解密阶段。

用户接受提取期间 LLDB 短暂暂停微信，并按助手提示重启或操作当前账号以触发数据库访问。不要求切换或处理其他本机账号。

## 非目标

- 不兼容微信 4.0 以下版本。
- 不绕过 macOS SIP、管理员授权或用户登录。
- 不持久化数据库密钥、聊天正文或未经脱敏的内存内容。
- 不在本次工作中重构聊天导出、消息解析或 HTML 生成逻辑。
- 不扫描、解密或导入当前登录账号以外的其他本机账号。

## 已验证现状

- 本机微信版本为 4.1.12，运行于 Apple Silicon。
- 现有 C helper 对 27 个 salt 扫描和单 salt 扫描都在 300 秒后超时。
- 社区微信 4.1.2 方案使用 `mov w0/x0, #0x43` 与 `bl malloc` 定位 WCDB `setCipherKey`。
- 微信 4.1.12 的 `WeChat`、`wechat.dylib`、`WCDY` 和 `WCDYWrapper` 中均未发现该精确指令锚点，因此不能复用固定的 4.1.2 定位规则。

## 方案选择

采用单一 LLDB 符号断点方案。微信 4.1.12 的 `wechat.dylib` 已实测通过系统 `CCKeyDerivationPBKDF` 执行 SQLCipher 派生，参数形状为密码 32 字节、salt 16 字节、迭代 256000。提取器只接受该形状，在同一助手进程内为当前账号所有数据库 salt 派生 raw page key并验证，不再扫描微信地址空间。

## 架构

### 1. 数据库清单与覆盖状态

Python 协调层先从微信当前运行状态解析唯一的当前账号目录，再扫描该目录的 `db_storage`：

- 记录账号目录、数据库相对路径、文件类型和第一页状态。
- 明文 SQLite 数据库直接标记为已覆盖，不要求密钥。
- 对加密数据库读取第一页 16 字节 salt，建立 `salt -> database references` 映射。
- 账号对外只使用任务内匿名标识；错误信息可以包含数据库相对路径，但不得包含账号 ID、salt 或 key。

覆盖状态只有三种：明文已覆盖、密钥已验证、未覆盖。所有加密数据库均为“密钥已验证”后才允许进入解密阶段。

### 2. LLDB 断点提取器

新增独立的 LLDB 提取组件，职责限定为：

- 附加明确 PID 的微信主进程。
- 对系统符号 `CCKeyDerivationPBKDF` 设置回调断点。
- 只接受 `(passwordLen=32, saltLen=16, rounds=256000)` 的实测参数形状。
- 断点命中后读取 32 字节密码并尽快恢复微信。
- 将候选字节交给 Python 验证器，不负责解密或写入状态文件。

定位规则不得依赖固定 ASLR 地址或单一微信小版本偏移。候选必须同时满足：

- 由微信进程调用系统 PBKDF2 符号；
- 参数长度和迭代次数匹配实测 SQLCipher 形状；
- 捕获密码派生出的 key 能覆盖当前账号全部加密数据库。

若无法得到唯一可信位置，提取器必须失败并分离，不能设置猜测性断点。

### 3. 候选验证器

候选验证器是两条提取路径共用的唯一真值来源：

- 校验捕获密码格式和长度，并按 PBKDF2-HMAC-SHA512、256000 次迭代为每个 salt 派生 raw page key。
- 优先用数据库第一页的 SQLCipher HMAC 进行内存内验证。
- 对 HMAC 参数不确定或需要交叉确认的数据库，使用 SQLCipher 执行只读 `sqlite_master` 查询。
- 验证成功后只在任务进程内维护 `salt -> key` 映射。
- 多个数据库共享 salt 时，一次验证可覆盖这些数据库，但仍需逐一检查文件第一页与数据库状态一致。

未经验证的候选立即丢弃，不进入日志、状态文件或 UI。

## 数据流与用户交互

### 用户必须理解的密钥规则

项目必须在开始提取前明确说明：

- 每个微信账号拥有独立的数据库密码，不同账号的密码和派生密钥不能互用。
- 同一账号只需成功捕获一次账号密码，即可结合该账号各数据库的 salt，派生并验证该账号本次任务中的全部数据库密钥。
- 首次导入某个账号时必须提取；切换到另一个账号后必须重新提取；微信升级、数据库重建或既有密钥验证失败时也必须重新提取。
- 仅重复导入同一账号且密钥仍在同一个运行中任务的内存里时可以复用；任务结束、助手重启、失败或取消后密钥会被清零，下次导入需要重新提取。
- 提取时必须确认微信当前登录的账号就是准备导入的账号。项目不得把当前账号密钥尝试用于其他账号目录。

这些规则至少在三个位置展示：

1. **提取前说明**：解释为什么需要提取、何时需要重新提取，以及一次只处理当前账号。
2. **账号确认与错误提示**：显示脱敏账号标识，要求用户确认；发现账号目录或密钥不匹配时明确提示切换账号后重新提取。
3. **完成提示**：说明本次仅完成当前账号，其他账号需要分别登录并重新运行提取与导入。

提示文案不得展示账号目录全名、密码、key 或 salt。用户必须主动确认已理解并确认当前账号后，工作流才能请求管理员授权和附加 LLDB。

1. 助手识别当前账号目录和全部数据库，生成覆盖清单。
2. 确认 SIP disabled 后，由用户完成一次管理员授权。
3. LLDB 附加微信主进程并定位断点。
4. 用户重启微信或操作当前账号以触发数据库初始化。
5. 断点命中后提取器读取密码、立即恢复微信并分离 LLDB。
6. 同一助手进程为当前账号全部 salt 派生 key并逐库验证。
7. 全部验证成功后，提示用户完全退出微信，再进行快照、逐库解密、`sqlite_master` 只读查询和聊天导入。
8. 任一数据库未覆盖、解密失败或元数据查询失败时，整次导入失败，不产生 partial 成功状态。

## 安全与隐私

- 仍要求用户手动关闭 SIP；程序不修改 SIP 或 NVRAM。
- 管理员权限只授予明确路径和明确 PID 的提取器。
- key 不出现在命令行参数、日志、异常、进度消息或持久化任务状态中。
- key 通过受控内存或 stdin 传递给验证/解密组件。
- 候选缓冲区在使用后清零；成功、失败、取消和异常退出都必须分离 LLDB 并恢复微信运行。
- 任务完成后仍停在 `awaiting_sip_enabled`，确认 SIP 恢复前不开放聊天读取和导出。
- 不读取或展示聊天正文来判断密钥是否正确，只查询 SQLite 元数据或验证密码学结构。

## 错误处理

- **定位失败**：未找到唯一可信调用点时立即分离并报告版本不受支持。
- **断点参数异常**：丢弃候选；连续异常达到上限后停止，防止错误断点持续影响微信。
- **微信退出或崩溃**：清空全部内存密钥并要求从头开始。
- **PID 变化**：视为账号切换边界，安全分离旧进程并重新定位新进程。
- **账号识别失败**：拒绝猜测账号目录，提示用户确认当前登录状态。
- **账号或密钥不匹配**：不得尝试其他本机账号目录；提示“每个微信账号密钥不同，请登录要导入的账号后重新提取”。
- **捕获超时**：分离 LLDB、恢复微信并清零内存密码。
- **部分覆盖**：整体失败；不得进入快照解密。
- **清理失败**：优先恢复微信运行和分离调试器，随后把任务标记为失败。

## 测试设计

### 单元测试

- Mach-O 模块筛选和候选指令评分。
- LLDB 断点参数的边界检查与解析。
- 当前账号数据库发现、重复 salt、明文 SQLite 和非法文件处理。
- SQLCipher 首页 HMAC 验证及错误参数组合。
- 覆盖状态聚合和全覆盖门禁。
- 超时、取消、进程退出及敏感信息脱敏。
- 缓冲区清理与调试器分离路径。

### 模拟集成测试

通过伪 LLDB 事件流覆盖：

- 当前账号重启、PID 改变和重新附加。
- 未确认密钥规则时拒绝开始提取。
- 切换账号后要求重新提取，且不复用前一账号的内存密钥。
- 首次导入、任务重启和密钥验证失败时显示重新提取提示。
- 单次断点命中覆盖多个共享 salt 数据库。
- 无效候选后捕获有效候选。
- 任一数据库缺失时拒绝进入解密。
- 中途取消、微信退出和扫描超时。

### 微信 4.1.12 真机验收

- 当前登录账号完成触发流程；本机其他账号不进入本次任务范围。
- 每个明文数据库被识别，每个加密数据库的 key 均通过首页密码学校验。
- 对全部数据库执行 SQLCipher `sqlite_master` 只读查询；为避免“抽样成功但冷库失败”，最终验收不采用抽样。
- 不产生 key 文件，不在终端、助手日志或异常中出现 key/salt。
- 失败或完成后微信正常运行或按流程正常退出，且不存在遗留 LLDB/helper 进程。
- 恢复 SIP 后，现有快照读取和导出门禁行为保持不变。

## 完成标准

以下条件全部满足才算完成：

1. 新提取器能在本机微信 4.1.12 上通过系统 PBKDF2 符号动态定位，而非依赖硬编码地址。
2. 一次工作流覆盖当前登录账号目录的全部数据库。
3. 全部加密数据库逐库通过密码学校验和 SQLCipher 元数据查询。
4. 任一未覆盖数据库都会阻止解密流程。
5. 自动化测试覆盖核心定位、验证、状态和清理逻辑。
6. 密钥、salt 和聊天内容不落盘、不进日志、不出现在 UI。
7. 用户重新开启 SIP 后，才能继续读取与导出。
8. UI 在提取前、账号不匹配和完成后三处准确说明账号密钥隔离及重新提取时机。

## 实现边界

预计改动集中在：

- `local_helper/wechat_macos/`：定位、LLDB 事件协调、候选验证和覆盖状态。
- 删除旧的原生内存扫描器和真机诊断脚本，不保留无效后备路径。
- `local_helper/api.py` 与本地助手页面：当前账号触发步骤和全库覆盖进度。
- `tests/`：单元测试、伪事件集成测试及真机验收说明。

不修改服务器端公共 API、聊天内容模型或现有导出格式。
