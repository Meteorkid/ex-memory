# 记忆闭环实现约定

用户已授权顺序：纠正入口 → 下一轮生效 → 长期归档 → 跨端一致 → 回答出处，并要求对应测试与完整验证。

- 复用现有镜像、纠正与归档实现，不新增依赖或数据库迁移；保持用户现有未提交改动。
- 网页每条已保存回答可明确提交纠正，IM提供显式指令。纠正引用只能来自当前账号、镜像和所选会话中已保存的回答；不接受客户端伪造来源正文。
- 共享材料修订号保存在镜像目录，Web和MCP缓存每次读取版本，覆盖独立进程；已开始的回复不撤回，后续请求读取新版本。
- conversation_id在账号+镜像范围内标识会话；旧记录归入web。IM默认按完整平台/会话/发送者派生独立ID，网页可选择IM会话继续。群聊与私聊不自动合并。
- 新会话归档按会话独立保存摘要，失败保留可重试批次，完成才推进。新摘要不写入全局人格或共用向量库，避免跨会话内容泄漏；人物原始材料和显式纠正属于镜像共享资料。
- 回答随附实际送入提示的有界sources快照，区分原始聊天、口述、生成摘要和旧对话历史。界面称“本次检索参考”，不声称逐句事实已被证明。
- sources按请求局部保存，不通过共享engine.last_sources传递。流式输出只有正常完成、审核通过且成功落库后才发送可纠正的metadata。
- 新API：GET conversations、GET conversations/{id}/messages、GET/POST corrections；私有响应no-store，校验登录和owner。新客户端发送conversation_id时使用服务端权威历史。
- 保留旧chat三元组与旧客户端history行为；新增带sources接口用于新闭环。新增MCP工具同样走持续令牌校验。
- 验证包括失败先行回归、跨端真实服务契约、源码快照、全量pytest/前端Node/静态检查及浏览器实际渲染。真实模型、平台发送和生产部署不在本轮执行。
