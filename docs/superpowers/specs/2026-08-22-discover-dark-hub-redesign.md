# 发现页暗色功能中心重设计

## 目标

完整重做 ex-memory 的“发现”页面及微信聊天导出面板，移除与 Midnight 暗色主题冲突的浅色卡片和旧式两行列表，同时保持朋友圈、助手检测、启动、轮询和安装包下载功能不变。

## 页面结构

### 顶部区域

- 使用“发现”主标题和简短副标题说明页面用途。
- 背景加入低透明度紫色径向光，不新增图片资源。
- 标题区与内容区保持主站现有间距和字体体系。

### 功能入口

- “朋友圈”和“微信聊天导出”改为两张并列功能卡，窄屏改为单列。
- 使用统一的内联 SVG 线性图标，不再使用 emoji。
- 每张卡包含功能名称、简短说明、状态标签和方向箭头。
- 保留 `moments-entry` 与 `wechat-helper-entry` ID；元素改为语义化 `button`，支持键盘操作。
- 当前选中的功能卡增加紫色描边、背景和光晕，并同步 `aria-expanded`。

### 朋友圈工作区

- 保留现有朋友圈数据和点击逻辑。
- 时间线使用深色表面、紫色弱分隔线和现有头像样式。
- 展开朋友圈时收起微信导出工作区，并激活朋友圈入口卡。

### 微信导出工作区

- 使用单个深色工作区容器组织内容，不再堆叠白色与浅橙卡片。
- 顶部展示“本机微信 4.x 导出”、本地处理隐私说明和绿色“仅在本机处理”标签。
- 助手状态使用深紫状态条；连接成功时允许由脚本切换状态文本。
- 主按钮使用项目紫色渐变，保持 `wechat-helper-launch` ID。
- 展示“连接助手 → 本机解密 → 生成 HTML”三步概览。
- 未签名 Beta 风险使用暗橙半透明提示条，不使用浅色背景。
- 下载区使用暗色卡片、紫色链接和等宽 SHA-256 文本，保持 `wechat-helper-downloads` ID。

## 视觉系统

- 页面和表面只使用现有 `--bg-primary`、`--bg-secondary`、`--bg-tertiary`、`--bg-elevated` 与 glass 变量。
- 主文本、次要文本、弱化文本使用 `--text-primary`、`--text-secondary`、`--text-tertiary`。
- 主交互使用 `--accent` 与 `--accent-hover`；本地隐私与成功状态使用 `--wechat-green`；Beta 风险使用 `--orange`。
- 卡片使用细紫色边框、项目圆角和暗色阴影，不出现 `#fff`、`#f5f5f7`、`#fff7ed` 等浅色表面。
- 支持 `prefers-reduced-motion`，减少动画时取消位移和过渡。

## 交互与状态

- 点击功能卡时只展开对应工作区，另一个工作区收起。
- 切换时维护入口卡的 `active` class 与 `aria-expanded`。
- 助手不可用、已连接、启动中和下载不可用状态沿用现有业务文案和 API。
- JS 继续使用现有 DOM ID，不改变 `/api/local-helper/config` 或 localhost 控制 API。

## 响应式与可访问性

- 桌面功能入口双列；小于 720px 改为单列。
- 功能入口、主按钮和下载链接具备清晰的 `:focus-visible` 状态。
- SVG 图标作为装饰时隐藏于辅助技术；按钮名称和说明保留文本。
- 不依赖颜色单独表达连接、风险或当前选择状态。

## 实现范围

- 重写 `web/static/index.html` 中发现页结构。
- 重写 `web/static/wechat-helper.css`，并定向调整 `web/static/style.css` 的发现页样式。
- 更新 `web/static/app.js` 与 `web/static/wechat-helper.js` 的入口激活状态，但不改变业务 API。
- 更新 Service Worker 静态资源版本，避免旧 CSS 缓存继续显示浅色页面。
- 不修改本地助手、SIP 状态机、聊天解析或导出逻辑。

## 验证

- 页面结构测试确认两个入口为按钮、SVG 图标、隐私标签、三步流程和暗色 Beta 提示存在。
- CSS 测试确认不再包含浅色回退值，并使用主站主题变量。
- JavaScript 语法检查与入口切换测试通过。
- 运行相关 pytest、Ruff、`node --check` 和差异检查。
- 重启本地网站并清理静态缓存版本，人工刷新确认页面加载新版样式。
