# macOS 本地微信完整导出设计

> 日期：2026-08-21
> 状态：待用户审阅
> 范围：公共网站 + macOS 本地助手，第一阶段仅支持 macOS 微信 4.x

## 1. 背景与目标

`ex-memory` 已支持通过 WechatExporter 从未加密的 iOS/Finder 备份导出微信聊天，但不能直接读取 macOS 微信 4.x 的本地加密数据库。

本功能的目标是：让用户在公共网站点击“导出本机微信”，由本机助手读取用户自己的 macOS 微信数据，在本机生成一份完整的离线 HTML 和分类媒体目录。聊天正文、联系人、wxid、数据库密钥、媒体和本地路径不上传网站服务器。

## 2. 已确认的产品决策

- 网站部署在阿里云，安装包由自有网站/CDN 提供下载。
- 本地助手长期作为“未签名开源 Beta”发布，用户手动放行 Gatekeeper/SmartScreen 警告；不规划购买 Apple 或 Windows 代码签名。
- 第一阶段只实现 macOS 微信 4.x；稳定后再实现 Windows 适配器。
- 原有 iOS/Finder 备份导出保留，不被新功能替换。
- 用户接受完全磁盘访问、辅助功能、管理员授权及导出期间短暂退出微信的要求。
- macOS 微信 4.x 直读作为“专家实验模式”：用户需在 Recovery 中手动临时关闭 SIP，完成密钥提取和快照解密后立即重新启用 SIP。助手不能自动改变 SIP 状态。
- 对本机未下载、已过期或已清理的媒体，保留原消息和缺失标记，不声称能恢复不存在的数据。
- 网站只负责安装引导、唤起和无隐私的任务状态；账号、联系人、数量预估与导出选择界面由 localhost 本地助手呈现。

## 3. 总体架构

```text
公共网站（FastAPI + 原生 JS）
        │
        │ health / launch / task-status
        ▼
macOS 本地助手（只监听 127.0.0.1）
        │
        ├─ local_api：配对、Origin 校验、任务状态
        ├─ wechat_macos：账号发现、取密钥、数据库快照与版本适配
        ├─ message_normalizer：统一消息模型
        ├─ media_resolver：媒体定位、复制、校验与转换
        ├─ html_exporter：离线 HTML 和清单
        └─ audit：脱敏诊断日志
                │
                ▼
        用户选择的本地输出目录
```

本地助手与网站使用小型、版本化的控制协议。未来 Windows 助手复用该协议，只替换数据发现、进程访问和数据库适配层。

## 4. 数据流程

1. 用户在网站点击“导出本机微信”。
2. 网站检测助手；未安装时展示下载、SHA-256 和手动放行教程。
3. 网站通过一次性深链唤起已安装的助手。
4. 助手在 localhost 本地页面中展示微信账号、联系人、消息数和媒体估算。
5. 用户选择会话和输出目录，然后在本机确认窗口中再次确认。
6. SIP 开启时，助手先做权限、磁盘空间和数据库可读性检查，然后给出 Recovery 风险说明。
7. 用户手动关闭 SIP 并重启后，助手只执行密钥提取、退出微信、只读快照和 SQLCipher 解密；密钥不落盘。
8. 解密快照写入当前用户独占的恢复任务目录，助手停止后续处理，要求用户立即回到 Recovery 执行 `csrutil enable` 并重启。
9. 助手确认 `csrutil status` 为 enabled 后，才解析消息、复制媒体、生成 HTML 并完成数量对账。
10. 助手在 Finder 中显示输出目录，清理恢复任务和临时解密库。

## 5. localhost 安全边界

- 助手仅绑定 `127.0.0.1`，不监听 `0.0.0.0`、局域网或公网网卡。
- 初次配对必须同时满足 Origin 白名单、一次性随机挑战、本机窗口确认和短时令牌。
- 拒绝 DNS rebinding、CSRF、错误 Origin、过期令牌、重放请求和路径穿越。
- 网站只能访问 `health`、`launch` 和无隐私 `task-status`；不提供返回联系人、正文、密钥、媒体或本地路径的 API。
- 联系人选择与导出确认页面属于 localhost Origin，公共网站不能读取其 DOM 和返回值。
- 每个导出任务使用一次性令牌。配对可随时撤销。
- 助手默认不访问公网；未来如增加“检查更新”，必须由用户显式触发。
- 即使公共网站前端被篡改，也不能从助手读取微信数据或绕过本机确认。

## 6. 本地数据安全

- 数据库原文件只读，所有解析使用快照。
- 解密数据库和中间产物放入当前用户独占的临时目录。
- 密钥默认不持久化，不写入日志、任务文件或导出清单。
- 任务完成、取消或失败后都必须清理密钥和临时解密库。
- 日志仅记录版本、阶段、数量、耗时和错误码，不记录正文、wxid、联系人、密钥或完整路径。

### 6.1 SIP 专家实验模式

- 只允许用户在 Recovery 中亲自执行 `csrutil disable` / `csrutil enable`；助手不提供自动脚本、不修改 NVRAM 或启动安全策略。
- 关闭前页面必须说明：重新启用 SIP 不能撤销关闭期间已发生的文件修改、持久化或数据泄露。
- SIP 关闭阶段只允许执行经固定哈希校验的内置密钥 helper 和 SQLCipher，不运行媒体转换、HTML 生成、自动更新或网络请求。
- 解密快照完成后立即停止，只写入不包含密钥的恢复状态。
- SIP 未重新启用时，禁止进入聊天解析、媒体复制和 HTML 生成阶段。
- 完成页面必须再次显示 SIP 当前状态；未确认 enabled 时不得标记导出成功。

## 7. 消息统一模型与覆盖范围

标准消息至少包含：消息 ID、会话 ID、时间、发送方向、发送者、原始类型、标准类型、文本/结构内容、引用关系、媒体引用和解析状态。

首版需覆盖：

- 文本、富文本、系统通知、撤回和拍一拍。
- 图片、实况照片、表情、动态贴纸、视频及封面。
- 语音原件及可播放派生格式。
- 文件、文件名、大小、扩展名和本地预览。
- 引用回复、合并转发及其嵌套消息。
- 链接、公众号文章、音乐、小程序、视频号和名片。
- 位置名称、地址、经纬度和本地存在的地图快照。
- 语音/视频通话类型、状态和时长。
- 转账、红包、收款等消息中本机可见的信息。
- 群成员、群公告、入群/退群和其他群事件。

未识别的新类型不得丢弃：HTML 显示原始类型编号和“尚未支持”，脱敏后的原始 XML/Protobuf 结构写入 `raw/`，并计入清单。

## 8. 导出目录契约

```text
联系人名(wxid)/
├── 联系人名.html
├── image/          # 图片原件与可用派生格式
├── video/          # 视频原件、实况照片视频部分
├── voice/          # 原始语音与 MP3/M4A 版本
├── file/           # 文档、压缩包及其他附件
├── emoji/          # 表情、动态表情和贴纸
├── music/          # 本地存在的音乐与封面
├── avatar/         # 账号、联系人、群和群成员头像
├── icon/           # 离线页面内置图标
├── thumbnail/      # 视频封面、文件预览和链接缩略图
├── location/       # 地图快照与位置结构
├── card/           # 链接、公众号、小程序、视频号卡片资源
├── raw/            # 未识别消息的脱敏原始结构
└── export-manifest.json
```

语音、HEIC 等需要转换的媒体必须同时保留原件和浏览器可用的派生文件。文件命名使用稳定内容哈希解决冲突，保留原文件名作为清单元数据。

## 9. HTML 契约

- 每个会话生成一个单独、可离线打开的 HTML，不依赖 CDN、远程字体、统计服务或服务端 API。
- 媒体使用相对路径，整个会话目录可直接移动。
- 支持微信风格气泡、头像、日期分隔、时间轴、关键词搜索、消息类型筛选、图片预览、音视频播放、引用跳转和合并转发展开。
- 大型会话使用分页或虚拟渲染，不一次性将全部消息 DOM 挂载到页面。
- 所有消息内容、XML 字段、文件名和卡片内容必须严格转义，禁止内联聊天内容作为可执行 HTML/JavaScript。
- 缺失或已过期媒体在原消息位置显示“资源不可用”及原因。

## 10. 完整性定义

导出结果分为三类：

- **完整**：数据库消息数、解析数和 HTML 消息数对账；没有未处理错误；所有本机可用媒体已复制和校验。
- **部分完整**：消息已保留，但存在未识别类型、已过期/未下载媒体、损坏文件或可恢复的单项错误。
- **失败**：数据库无法安全快照/解密，数量无法对账，或输出无法完成原子提交。

`export-manifest.json` 记录消息总数、各类型数量、媒体成功/缺失/损坏数量、微信版本、schema 指纹、导出器版本、校验值和最终状态，不记录密钥。

## 11. 权限策略

1. 助手启动和环境检测时不申请高权限。
2. 用户点击“扫描微信”时才引导完全磁盘访问。
3. 只在用户已手动关闭 SIP 且再次确认风险后，才在微信 4.x 取密钥时申请管理员授权和辅助功能权限。
4. 只在选择输出目录时请求目标目录访问。
5. 不申请相机、麦克风、通讯录或局域网监听权限。

## 12. 异常处理

- 启动时检测 macOS 版本、CPU 架构、微信版本、登录状态、权限和剩余空间。
- 只允许已经“微信版本 + schema 指纹”验证的组合进入正式导出；未验证组合只提供脱敏诊断。
- 取密钥失败时显示具体可执行步骤，不循环触发管理员弹窗。
- 微信退出、快照与重新打开分别记录状态；导出失败也尝试恢复微信运行。
- 单个媒体损坏不终止整个任务，但必须将结果降级为“部分完整”。
- 支持取消。取消后清理敏感临时文件，已生成目录显式标记“未完成”。
- 预估空间不足时在复制前终止。
- 输出先写临时目录，完成校验后原子更名。
- 同一会话重复导出默认创建带时间戳的新目录，不覆盖旧结果。

## 13. 技术与发布方案

- 本地助手继续使用 Python 技术栈，打包为自包含 macOS `.app`。
- 分别发布 Apple Silicon (`arm64`) 与 Intel (`x64`) 压缩包。
- 可使用免费 ad-hoc 签名保证 App Bundle 结构完整，但这不是 Developer ID 签名，不得在文案中声称已经 Apple 认证或公证。
- 用户不需要预装 Python、Node.js、Homebrew 或 SQLCipher。
- SQLCipher、媒体转换工具和 HTML 模板随应用打包，并在第三方许可声明中记录来源和许可证。
- 高权限范围限制在小型原生 C helper，用于读取微信进程内存并返回密钥候选；其他流程不使用管理员权限。
- 原生 helper 受 SIP 与微信 Hardened Runtime 限制；专家模式明确依赖用户手动临时关闭 SIP，且不保证未验证的 macOS/微信版本可用。
- 首版不实现静默自动更新。

网站下载目录示例：

```text
/downloads/
├── ex-memory-helper-<version>-macos-arm64.zip
├── ex-memory-helper-<version>-macos-x64.zip
├── SHA256SUMS
├── build-manifest.json
└── RELEASE_NOTES.md
```

安装页展示版本、架构、文件大小、SHA-256、对应源码 commit，以及 Gatekeeper、完全磁盘访问、辅助功能和管理员授权的用途说明。阿里云下载防篡改和独立校验值发布不属于当前实施范围，但发布格式保留后续加固能力。

## 14. 测试与验收

### 14.1 数据安全

- 导出前后的微信数据库原文件哈希必须一致。
- 任务结束后不得残留密钥或临时解密库。
- 恶意网页、错误 Origin、过期令牌与重放请求不能调用敏感操作。
- 公共网站前端被替换的模拟情况下，也不能获取联系人、聊天正文、密钥和媒体。

### 14.2 完整性与格式

- 数据库消息总数、解析消息数、HTML 消息数和清单数量必须对账。
- 已识别消息全部进入 HTML；未识别消息全部进入 `raw/`。
- 媒体按成功、缺失、损坏和转换失败分类计数。
- HTML 在断网情况下可用，Safari 和 Chrome 能打开支持的媒体。
- 聊天中的 HTML、JavaScript、畸形 XML 和特殊文件名不得形成代码执行或路径穿越。

### 14.3 性能与兼容

- 十万至百万级消息能够分批解析、生成和浏览。
- 大型媒体目录使用流式复制与增量进度，不将全部内容读入内存。
- 在 Apple Silicon 和 Intel Mac 上分别验证。
- Beta 页明确展示已验证的微信版本与 schema 指纹，未验证版本不标记为兼容。

### 14.4 测试分层

- 单元测试：路径安全、消息映射、XML/Protobuf 解析、媒体定位、HTML 转义。
- 契约测试：网站与助手的有限 API。
- 安全测试：Origin、CSRF、DNS rebinding、令牌重放、路径穿越、恶意聊天内容。
- 集成测试：脱敏后的微信 4.x 数据库快照。
- 端到端测试：从网站点击到 Finder 显示结果。
- 输出回归：与参考导出目录对比结构、数量与媒体可用率，不将真实聊天数据纳入仓库。

## 15. 非目标

- 不恢复本机已不存在的媒体。
- 不上传、云端解密或云端生成聊天导出。
- 不修改微信数据库或应用文件。
- 不在第一阶段实现 Windows、Linux、Android 或直接读取 iOS 设备。
- 不购买代码签名、不提交 Mac App Store、不实现静默自动更新。
- 不自动关闭/开启 SIP，不隐藏 SIP 风险，不在 SIP 关闭时执行最终导出或联网。
- 当前阶段不实施阿里云防篡改、对象锁定或独立发布签名链路。

## 16. 后续阶段

1. 完成 macOS 微信 4.x 的数据发现、解密、消息解析和完整导出。
2. 通过脱敏回归样本和实机 Beta 稳定 schema 适配。
3. 在不改变网站控制协议的前提下，新增 Windows 本地助手适配器。
4. 根据实际用户量，再评估阿里云下载防篡改和发布供应链加固。
